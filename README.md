# FIRE STORM — браузерная версия (сервер + клиент)

Играть можно прямо в браузере телефона (Android, iPhone) и компьютера. Ничего устанавливать не нужно.
Сервер на Node.js отдаёт саму игру и связывает игроков через WebSocket, поэтому достаточно одной публичной ссылки.

## Что входит в проект
| Файл | Для чего |
|---|---|
| `server.js` | сервер: аккаунты, комнаты по коду, дуэли, боты, друзья, кейсы |
| `public/index.html` | вся игра (меню, 3D, управление ПК и телефона) |
| `package.json` | зависимости (`ws`, `better-sqlite3` 12.11.1), версия Node 22 и команда запуска |
| `render.yaml` | готовая настройка для Render (платный вариант с диском) |
| `.node-version`, `.gitignore` | версия Node (22.22.0) и список файлов, которые не нужно загружать. Имена начинаются с точки, на компьютере они могут быть скрыты: проверьте, что они попали в репозиторий |

## 1. Запуск у себя (проверка)
Нужен Node.js 22 LTS (проект закреплён на 22: версия записана в `.node-version`, `package.json` и `render.yaml`). Node 24 и 26 не используйте: для них у `better-sqlite3` 11.x нет готовых сборок.
```
npm install
node server.js
```
Откройте http://localhost:3000. Чтобы проверить с телефона в той же Wi‑Fi сети, откройте `http://IP-компьютера:3000`.
Игра с другом из другого города возможна только после публикации (раздел 3).

## 2. Загрузка на GitHub
1. На github.com создайте пустой репозиторий (New repository), например `fire-storm`.
2. Нажмите «uploading an existing file» и перетащите **содержимое** этой папки (не саму папку), чтобы `package.json` лежал в корне репозитория:
   `server.js`, `package.json`, `README.md`, `render.yaml`, `.node-version`, `.gitignore` и папку `public` с `index.html`.
3. Не загружайте: `node_modules`, файлы `*.db`, папки `_backup_*`, `fire-storm-server` (устаревшая версия).
4. Нажмите «Commit changes».

## 3. Публикация на Render (публичная ссылка)
Зарегистрируйтесь на render.com и подключите GitHub.

**Вариант А. Бесплатная проба.** New → Web Service → выберите репозиторий. Runtime: Node. Build Command: `npm install`. Start Command: `node server.js`. Instance Type: Free. В Advanced добавьте Health Check Path `/health`. В разделе Environment добавьте переменную `NODE_VERSION` со значением `22.22.0` (она имеет наивысший приоритет и надёжнее файла). Нажмите Create.
Ограничения бесплатного тарифа по документации Render: сервис засыпает после 15 минут без запросов и просыпается около минуты; файловая система временная, поэтому **аккаунты и прогресс стираются** при каждом перезапуске, засыпании и новой публикации. Подходит, чтобы попробовать игру с друзьями, но не для постоянных аккаунтов.

**Вариант Б. Постоянные аккаунты.** New → Blueprint → выберите репозиторий: Render прочитает `render.yaml` (платный сервис Starter с диском 1 ГБ). База хранится в `/var/data/firestorm.db` и не пропадает. Актуальную цену смотрите на странице Pricing на render.com (на момент проверки: сервис от 7 $/мес и диск около 0,25 $ за ГБ в месяц). Вместо Render можно взять любой хостинг с постоянным диском и поддержкой WebSocket, на нём задайте `PORT` и `DB_PATH`.

После публикации Render покажет адрес вида `https://fire-storm-xxxx.onrender.com`. Это и есть публичная ссылка на игру: HTTPS и защищённый WebSocket (wss) подключаются автоматически.

## 4. Как играть
- **Телефон:** откройте ссылку в Chrome (Android) или Safari (iPhone), держите телефон горизонтально. Для режима без адресной строки: меню браузера → «Добавить на главный экран» → запускайте иконку. Управление: джойстик слева, камера свайпом по правой части, кнопки «Огонь» и «R».
- **Компьютер:** W A S D, мышь (клик по экрану захватывает мышь), левая кнопка стрельба, R перезарядка, Esc пауза.
- **С другом:** оба регистрируются (АККАУНТ), затем DUEL 1 VS 1 → «Создать комнату», код вида `DUEL-1234` отправьте другу, он вводит его в «Присоединиться по коду». Когда оба нажмут «Готов», матч начнётся. Записывайте код восстановления, он показывается один раз.

## 5. Что реально проверено, а что нет
Проверено автоматически (сервер с настоящей библиотекой `ws` по сети, два экземпляра клиентского кода в Node):
- сервер запускается, отдаёт игру и `/health`; выход за пределы папки `public` заблокирован;
- регистрация, вход по сохранённому токену, неверный пароль, вход со второго устройства (прежнее закрывается, без бесконечного выбивания);
- комната и вход по коду, быстрая дуэль, друзья и приглашение, дуэль с ботом;
- движение одного игрока видно другому (около 0,2 с на одном компьютере), выстрел с «сенсорного» клиента убивает «компьютерного», счёт и экран итогов у победителя;
- этапы исправлений 1–4 и поведение ботов (ножевые и огнестрельные, все уровни).

**Не проверено (нужен реальный телефон, браузер и интернет):**
- как игра выглядит и управляется на Android и iPhone: размеры кнопок, поворот экрана, полноэкранный режим, масштаб, 3D-графика и скорость на слабых телефонах;
- вид интерфейса на разных разрешениях компьютера, захват мыши;
- игра двух людей через интернет (задержка, обрывы связи, переподключение в матче);
- установка `better-sqlite3` и запуск на самом Render (в тестах SQLite заменён встроенным);
- нагрузка при многих одновременных матчах.

Известные ограничения: нет звуков; на телефоне нет прыжка и приседания; fullscreen на iPhone Safari недоступен (поможет «Добавить на главный экран»); для 3D-движка (three.js) браузеру нужен доступ к cdnjs.cloudflare.com.

## 6. Если сборка на Render упала
- В журнале должна быть строка вроде `Detected Node version 22.x`. Если там 24 или 26, добавьте/исправьте переменную `NODE_VERSION` = `22.22.0` в Environment сервиса и нажмите Manual Deploy → **Clear build cache & deploy**.
- Порядок выбора версии у Render: переменная `NODE_VERSION` → файл `.node-version` → `.nvmrc` → `engines` в `package.json`. В `engines` обязательна верхняя граница (здесь `<23.0.0`), иначе Render берёт самую свежую версию Node.
- Если в журнале сообщения `node-gyp` и `better_sqlite3.o`, значит, сборка снова пошла на неподходящей версии Node (см. пункт выше).
